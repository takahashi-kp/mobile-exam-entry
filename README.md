# 出張健診 検査項目入力

ブラウザで動くローカルファーストの入力アプリです。

- ローカル保存: IndexedDB
- オフライン対応: Service Worker
- クラウド同期: 画面の「同期」タブで REST API URL と APIキーを設定
- 対応画面: スマホ、タブレット、PC
- 連名簿出力: 選択中の予定グループから胸部XP・胃部XPの巡回照射録をExcelで出力
- X線入力: 胸部・胃部を個別に開閉し、それぞれの備考を保存。塵肺・アスベストは胸部内で入力
- 検査入力: 「入力」から検査グループを選び、選択した検査だけを独立画面で入力
- 巡回診察: 保存済みの検査結果と問診結果を参照しながら診察所見を入力
- 検査結果確認: 各検査画面で「登録（仮保存）」後、利用者が結果を確認して「確認」。未入力・仮保存・確定を画面と一覧に表示
- バーコード連続受付: 検査の確認後は個人番号欄を選択し、次の受診者をバーコードで読み込める
- 採血本人確認: 複数の採血管バーコードを個人番号・氏名と照合して履歴表示。不一致時は確定を防止し、確認時に受付番号を最大値+1で自動採番

## 特定保健指導の年齢判定

- 下限は年度末年齢40歳以上で判定します。
- 上限は受診日当日に75歳未満であることに加え、75歳の誕生日の6か月前より前に受診していることを条件とします。
- 受診日に74歳で対象となる場合は、判定欄に保健指導完了期限を表示します。

## 使い方

`index.html` をブラウザで開きます。PWA/オフライン機能まで確認する場合は、ローカルサーバーで開いてください。

```powershell
python -m http.server 4173
```

その後 `http://localhost:4173` を開きます。

## FeliCa本人確認（Windows 11 + PaSoRi RC-S300）

有償SDKは使用せず、同梱のUSB読み取りプログラムでカードのIDm、PMm、FeliCa Lite-Sのユーザーブロックを読み取ります。RC-S300の両インターフェースには、事前にZadigでWinUSBドライバーを設定します。

1. PaSoRiを接続し、`start-felica-helper.bat` をダブルクリックします。
2. 「受付」画面で受診票の個人番号を読み取り、本人情報を確認します。
3. 「本人確認済み・カードを置く」を押してFeliCa Lite-Sを置き、受付を完了します。
4. 各検査画面ではカードを置くか「カード読取」を押すと、検査画面を維持したまま紐付いた受診者へ切り替わります。

補助アプリは `127.0.0.1:8765` だけで待ち受けます。紐付け情報は `%LOCALAPPDATA%\MobileExamFelica\bindings.dat`、読み取ったカードバックアップは `%LOCALAPPDATA%\MobileExamFelica\card-backups.dat` にWindowsユーザー単位のDPAPIで暗号化して保存します。バックアップにはSHA-256を付けます。

### カード内バックアップ形式

- 14ブロックを7ブロックずつのA/B二重スロットとして使用します。
- 各スロットは確定ヘッダー1ブロックとデータ6ブロックで、データ容量は最大96バイトです。
- 更新時は古い有効スロットを残し、反対側へデータを書いて1ブロックずつ読み戻し照合します。
- 最後にCRC32付きヘッダーを書き、読み戻した内容が有効になった場合だけ完了とします。
- ローカルAPIの書込みは、IDm、`allowWrite=true`、確認文字列`WRITE_AND_VERIFY`がすべて一致した場合だけ実行します。書込み前には必ずDPAPI暗号化バックアップを保存します。
- 検査画面の「確認」はカードの有無を自動判定します。カードがあれば端末確定後にFeliCaへ反映し、カードがなければ端末確定だけを行います。書込みに失敗しても端末保存は維持され、同じ「確認」から再実行できます。
- カードの健診ペイロードは最大96バイトです。氏名、個人番号、備考は記録せず、予定グループと個人番号から作る照合用ハッシュ、確認済みグループ、主要な数値・判定のみを格納します。
- 「受付」画面では受診票の個人番号を読み取り、本人確認後にカードを置くと受付処理を開始します。カードの2保存領域を今回の受付データで上書き・検証してから受診者へ紐付けます。
- カード、PaSoRi、補助アプリが使えない場合は「カードなしで受付」を選択できます。受付履歴は端末内に残り、各検査では受診票の個人番号を読み取って運用します。
- 各検査ブースでは担当する検査画面を開いたままにできます。受付済みカードを置くと、そのカードの受診者へ自動的に切り替わります。前の受診者に未登録入力がある場合は切替を止めます。
- 採血は採血管バーコードが個人番号と一致した時点で端末確定します。カードが置かれている場合だけ「確認」を表示してFeliCaへ反映し、カードなし運用ではそのまま次の受診者へ進めます。
- 端末データを失った場合は「カード復元」を使用します。予定CSVを再取込みして対象グループを選び、カードを1枚ずつ読むと、照合用ハッシュから個人番号を特定して確認済み検査値を端末DBへ追加します。
- 復元できるのはカードに保存した構造化検査値です。氏名・性別・生年月日は予定CSVから戻します。備考、自由入力、採血確認ログはカード容量と個人情報保護のため保存しておらず、復元対象外です。
- 暗号化バックアップはカードごとに直近20世代を保持します。

## クラウド同期API

設定したURLに、未同期レコードを `POST` します。APIキーを設定した場合は `Authorization: Bearer <APIキー>` を付けます。

クラウド読込では、同じURLに `GET` し、レコード配列を受け取ります。

### 複数端末・オフライン同期

- 入力内容は最初に各端末の IndexedDB へ保存します。
- オンライン時は保存後に自動送信し、画面切替、画面復帰、オンライン復帰、30秒間隔で自動読込します。
- レコードは「予定グループ + 受診者コード + 検査グループ」の安定したキーで統合します。
- クラウド読込では未同期・同期失敗のローカル値を上書きしません。
- 空欄の値で既存の測定値を消さず、サーバーは受信した各版を `sync_record_history` に保存します。
- 同じ検査項目へ複数端末から異なる非空値が届いた場合、表示値は後着を採用しますが、過去の受信値は履歴に残ります。

同梱の `cloud_api_example.py` は最小の同期APIです。社内サーバーやクラウドVMに置いて起動し、アプリの同期URLに `http://サーバー名:8787` を設定します。

## 連名簿Excel出力

予定管理でグループを選択して予定日を保存し、上部の「連名簿」を押します。胸部・胃部を個別に作成するか選択できます。Macの対応ブラウザでは保存先フォルダーを選択し、Windowsではブラウザの通常ダウンロードとして選択したファイルを保存します。

- 胸部: 胸部X線フィルム番号がある受診者、塵肺・アスベストの個別区分と合計件数。E2の見出しは対象データに応じて「塵肺件数」または「アスベスト件数」
- 胃部: 胃部X線フィルム番号がある受診者
- 共通: 顧客名、撮影日、氏名（カナ）、性別、年齢、撮影番号、撮影件数

## 受診予定CSV

予定管理の「CSVフォーマット」から取込用ファイルをダウンロードできます。必須列は `受診者コード`、`氏名`、`カナ氏名`、`性別名称`、`生年月日` です。予定管理で保存した予定日は、連名簿の撮影年月日とCSV出力ファイル名に使用します。

予定管理のグループ名は一覧上で編集できます。変更した名前は、同じグループに属する予定・検査・問診データにも反映してクラウド同期します。

不要になった予定グループは、グループ名を再入力してアーカイブできます。アーカイブでは予定・検査・問診データを削除せず、全端末の通常一覧から非表示にします。「アーカイブ済みを表示」からいつでも復元できます。

```powershell
python cloud_api_example.py
```

## GitHub / Render で共有する

このアプリは Flask API と PostgreSQL を使用するため、Render では Python Web Service として公開します。

### GitHub に置く手順

```powershell
git init
git add .
git commit -m "Initial mobile exam entry app"
git branch -M main
git remote add origin https://github.com/<ユーザー名>/<リポジトリ名>.git
git push -u origin main
```

### Render に載せる手順

1. Render の Dashboard で New > Blueprint または Web Service を選びます。
2. GitHub のリポジトリを接続します。
3. Blueprint を使う場合は、このリポジトリ直下の `render.yaml` を選びます。
4. 手動設定する場合は以下にします。

```text
Build Command: pip install -r requirements.txt
Start Command: gunicorn server:app
```

公開後は `https://<サービス名>.onrender.com/` で開けます。

`DATABASE_URL` と、必要に応じて `SYNC_API_KEY` を設定します。秘密情報はGitへ保存しないでください。
